# Collector 2.0 Implementation Plan

> Execution: inline with executing-plans; isolated public-project checkout.

**Goal:** Reproducible read-only collection and local aggregate analysis, default 2025.
**Architecture:** Keep the 1.x builder as a legacy compatibility tool. Version 2 uses
one normalized event export with guarded schema adapters, rather than repeating the
same large source query in every metric dataset. Python owns definitions and caching.
**Stack:** Python, pandas, openpyxl, Plotly, SQLite, SQL Server, RDL 2016.

- [x] Add tests in tests/test_v2_analysis.py and tests/test_v2_collector.py.
- [x] Run: python -m pytest tests/test_v2* -q; verify missing 2.0 behavior fails.
- [x] Cover 2025 defaults, period reason, interval union, exact30, invalid times,

## 3. Collector
- [x] Create tools/build_collector_v2.py and sql/v2 definitions. Reuse existing
  RDL rendering helpers, not legacy metric SQL.
- [x] Guard every source column before dynamic SQL compilation; hard stop on
  missing required identity/date/test-patient columns; typed NULL optional anchors.
- [x] Export source availability, confirmed watermark, context start, period reason.
- [x] Export appointments including cancelled and non-patient blocks, technical
  events including brachy; hash identities with run-local salt. Never export
  personnel/room resource names or notes. Resolve device resources via DimMachine.
- [x] Bound history joins to exported appointments; use temp indexes.
- [x] Build and validate XML, fields, parameters, privacy allowlist and SQL contract.
